## Findings from the first consumer (docs-compression experiment)

The harness-llmify-prototype experiment's Phase 0 smoke tests (Claude Code 2.1.197, headless `-p` runs; archived transcripts under `~/workspace/harness-llmify-prototype/runner/archive/`) exercised the full chain on fresh production logs: `sessions --session-id` direct locate, `convert`, `stats`, `drift scan`. Parsing was fully correct, with strong external cross-checks: `stats` token totals match the harness's own JSON result envelope exactly, `final_answer` matches captured stdout byte-for-byte, and `fetch_raw_bytes` (24,747) matches the experiment server's access-log bytes-served for the same request, while the WebFetch tool-result payload records the 1,162-byte small-model summary the model actually saw. That raw-fetched vs. model-visible split is the measurement the experiment most needs, confirmed working. Two items to fold back in:

1. **Claude-code drift baseline under-covers search tools** (**resolved**). `drift scan` on the filesystem-retrieval transcript exited 1 with additive vocabulary: tool names `Glob` and `Grep` (never probed), their `user` result keys `toolUseResult.{countIsComplete, filenames, mode, numFiles, numLines, totalMatches, truncated}`, `assistant.supersedesUuids`, and `system` keys `{apiRefusalCategory, apiRefusalExplanation, direction, fallbackModel, originalModel, refusedUserMessageUuid, requestId, retractedMessageUuids, trigger}` (a refusal → model-fallback → retraction flow). The parser handled every record, so this was baseline under-coverage, not format breakage. Resolution: a claude-code-only `search` probe (Glob + Grep over a seeded workdir) joined the probe set — with two empirical wrinkles: headless 2.1.197 does not register Glob/Grep at all unless they are named in `--allowedTools` (probes gained an `ExtraArgs` field; the experiment's own runner already passed that flag, which is why its transcripts had them), and the checker is name-exact because ToolSearch is also kind `search`. Probing also exposed that the mtime window swept in transcripts of concurrently active sessions, so probe orchestration now filters claimed transcripts by recorded cwd (third orchestration fix, after the two from the shakedown). Baseline regenerated from fixtures + local corpus (which contains the smoke-test originals); the synthetic fixture `harness/claudecode/testdata/search_fallback.jsonl` pins the Glob/Grep envelopes and the refusal/fallback flow and joined the scan-clean invariant; inventory updated. All three archived smoke-test transcripts now `drift scan` clean (exit 0), so the experiment can gate archiving on the exit code.
2. **`convert` skip-report parity between output formats** (**resolved**). The `json` format's `report.skipped_records` names skipped types with counts, satisfying the never-silently-drop rule, but the `jsonl` stream printed only a count on stderr ("19 events, 4 skipped records"), so a streaming consumer could not assert that only documented-skip-list types were dropped without re-running in json mode. Resolution: the jsonl stderr summary now carries the same per-type breakdown ("19 events, 4 skipped records (ai-title 1, last-prompt 1, queue-operation 2)").

Round two: the experiment wired its Codex and Antigravity adapters and smoke-tested fs + web-md on both (archives in the same location, `codex_*` and `antigravity_*`). All four transcripts detect certain, drift scan clean on first contact (the baselines fully covered these workloads), skip accounting is clean (codex: 3 benign `event_msg/*` skips; antigravity: 0), Codex session discovery by recorded cwd and Antigravity discovery by time-window scan both resolved correctly, and Antigravity's side-file fetch chain is fully captured (`read_url_content` result names the side file; the follow-up `view_file` result carries the model-visible content, 28,940 B for a 24,747 B page). `stats.final_answer` also proved load-bearing: the experiment runner now uses it as the judgeable answer for Antigravity, whose `--print` stdout wraps the answer in step narration and a "Summary of Work" section. ## Context for the format-drift infra session

Decision recorded in DEVELOPMENT.md ("Harness format versioning"): parse by shape, not by version; union parsers plus version-stamped fixtures, no version-dispatched parsing and no behavior-changing version flag. The infra ideas below should build on that.

Design for the drift tool: `drift-probe-design.md` (**built**: `internal/driftprobe/` + `agentminutes drift` with scan visible and probe/baseline hidden). On-demand, version-gated against `harness.LastValidated`, with shape assertions to guard against vacuous probes and a vocabulary-baseline diff to catch additive drift strict parsing tolerates. Deliberately no cron, no passive corpus sweep, no CI. Shaken down against all three real harnesses with `--force`: antigravity fully clean; claude-code and codex each surfaced real additive vocabulary (reconciled into the baselines; findings recorded in the inventories). Two orchestration fixes came out of it (mtime-window dedupe across probes, file-probe prompt forbidding shell redirection). Codex's fetch probe is inconclusive by construction on 0.144.1 (fetch leaves only telemetry; see the codex inventory).

The problem: all three formats drift fast (Codex changed shell-call mechanism, output shapes, and record vocabulary between 0.118 and 0.144; Antigravity fixes headless bugs per point release; Claude Code adds record types and envelope fields across 2.1.x). Today, drift is caught only when someone runs the env-gated local-transcript tests.

What already exists to build on:

- Env-gated strict-parse tests with per-line accounting per adapter (the drift detectors; they fail loudly on new record types).
- Scripted probe recipes per harness (DEVELOPMENT.md step 0): headless one-liners per tool family that generate fresh ground truth cheaply. Antigravity probes cost real quota (Google AI Pro subscribed); Codex/Claude probes are cheap.
- Version pinning conventions: inventories record observed harness versions; Claude Code stamps its version per record, Codex in session_meta, Antigravity nowhere (brew version must be recorded externally).
- `Sniff` confidence grading, which could double as a cheap format-fingerprint check.

Ideas discussed but not designed (for the next session to weigh): a script/cron that runs the probe recipes against currently-installed harness versions, strict-parses the fresh transcripts, and diffs the observed record/field vocabulary against the inventory docs; a version-stamped fixture corpus so old formats stay covered as new ones land; surfacing "unknown telemetry subtype" system events (Codex) as drift signals rather than silently mapping them forever.
